# 脚本说明（目的 / 用法 / 重建指引）

> 每个脚本的头部注释都写了"目的 + 实现要点"。本文是**总索引与重建指引**：
> scripts/ 下**可能有预制脚本，也可能没有**（或部分损坏）——缺失/报错时按本文现场重建或修复。
> 完整业务规则见 `设计规则.md`；本文只讲脚本。

## 〇、通用

- 语言：Python 3（依赖：`fonttools` 仅 setup_fonts 用；下载/压制依赖 yt-dlp / node / yt-dlp-ejs / curl-cffi / ffmpeg——见设计规则 §1.1）。
- 所有脚本独立运行、互不 import 业务代码（仅 build_* 与 preview_style import `sub_style.py`）。
- **重建后的验收**：`python -m py_compile scripts/*.py` + 各脚本冒烟（见文末）。

## 二、逐脚本：目的与重建要点

### sub_style.py（样式与输出·最重要）
- **用法**：`python sub_style.py <lines.jsonl> <out.ass|.vtt|.srt> [--mode bilingual|zh|src] [--order zh-src|src-zh] [--preset default]`
- **目的**：全技能唯一的"样式真相"。默认款（细节见脚本顶部注释）：中文 普惠体 **95 ExtraBold**（真字重）/**82 号**/白/描边 **2.0**/底距 **121**（底部锚定）；原文 **Alibaba Sans Bold**（阿里配套拉丁字体）/**62 号**/#E8E8E8/描边 **1.2**/首行顶距 **950**（顶部锚定）；上下可切（order）；三态（bilingual/zh/src）——**单中文底距 80、单原文底部锚定底距 80**（预设 `zh_only_mv` / `src_only_mv`，`ass_header` 按 mode 覆盖）。
- **重建要点**：槽位(锚定+边距)与内容(字体/字号/色)分离；**SRC 事件固定 Layer 1、ZH 固定 Layer 0**（写死，勿丢）；ASS 时间戳恰好 2 位百分秒、VTT/SRT 3 位毫秒；清理函数 strip_zh/strip_src/zh_len 属共享工具（build_* 也用）；`preset_for(name, font_mode)`（`system`=系统字体档：中文 Microsoft YaHei / 原文 Arial）与 `load_style_from_ass(path)`（采纳用户示例 ass 的字体/字号/颜色/描边，布局不变）也在这里。
- **zh_len 行宽计法（定规）**：标点**占位**（书名号/逗号各 1、破折号——按 2），只豁免行尾 ，。,.；英文/数字每 2 个算 1、空格 0.5；**最优 10、硬上限 16**。
- **坑**：两条样式都底部锚定会让中文随原文行数浮动 → 必须"中文底部锚定 + 原文顶部锚定"；**libass 防重叠会把同层相邻槽位钉住**（边距调 14px 只动 2px）→ SRC 走 Layer 1 分层即彻底绕开；build_auto 机检重解析 ASS 需按"层号任意"匹配。

### download.py（下载）
- **用法**：`python download.py <url> [--base DIR] [--quality 1080p60] [--vcodec av1|vp9|h264|any] [--no-video] [--proxy URL] [--proxy-mode external|internal] [--cookies FILE] [--track KEY] [--check-only]`
- **目的**：一条命令完成探测+选轨+下载+建目录（**两级结构：源视频放一级，字幕与 decision/probe 等中间文件放二级 `中间文件/`**）。三级选轨：①人工简体中文→直用；②人工源语言→翻译；③自动 `-orig`→翻译；多 `-orig`（自动配音）用 `info['language']` 消歧；判不了打印"[需决策]"退出（由 AI 决策，`--track` 为隐藏参数）；**①命中时探测源语言轨（人工优先、无人工取自动）→ decision.json 记 `track_src`/`src_kind` 并两轨一起下载**（"中源双语"两轨直出用，见 SKILL §五 B-①b）。**下载方式默认 HLS 分片（`-N 8` 并发）→ 实得 VP9**（HLS 无 AV1；备用：默认客户端 → web_embedded）；`--vcodec av1|vp9|h264|any` 可切（**明确 av1 时自动改走 DASH 客户端**）；音频优先 m4a/AAC。
- **坑**：缺 curl-cffi → 403 "Only images available"；瞬时 403 → 内建重试；清 *_PROXY + 显式 --proxy；--js-runtimes node 必需；输出命名 `[制作者] 标题-YouTube`（非法字符替换）；**YouTube 瞬时降级会把视频静默下成 360p 旧格式（退出码仍为 0）→ 下载后必须 ffprobe 校验分辨率、不达标删除重试最多 3 次**；**媒体流 403（SABR/PO Token）下载方式优先级：HLS 分片（`-N 8` 并发，默认）→ 默认客户端 → web_embedded**；**重跑/复下：不覆盖、不删除已存在文件——同名视频已存在时，本次下载自动保存为 `<名称>(2).mp4`（旧文件保留）**；下载验收只认精确名（不误抓同前缀的 `.hardsub.mp4`）（见设计规则 §2.5；两条都不行则报告用户，不用第三方下载站）；**画质是交互项**——探测后 `quality_available()` 检查该档位（含帧率）是否存在，不存在就 `[需决策]` 退出（退出码 2）并列可用画质，等用户确认后 `--quality` 重跑；存在则**每个下载方式都带 `[height<=H]`**，验收看"不超上限"（`final_h <= cap`）；`--quality` 只认规定写法，不认识的**直接报错**。

### parse_json3.py（自动·步骤1）
- **用法**：`python parse_json3.py <json3或srt> <输出目录>`（写 elements.json + stream.txt）
- **目的**：元素绝对时间 = tStartMs + tOffsetMs；机械去噪只删换行（收条）/`[...]`/`>>`；密集编号；文本保留原样。
  **stream.txt 是纯词流（无编号、每行 12 个词）**——AI 只读文本不写编号（编号由 bind_ids 机械绑），
  去编号省约一半阅读量；每行 12 词的结构供 AI 按行分块/续跑。
- **坑**：`">> [laughter]"` 粘连形态剥完必须**复检 [] 标签**（否则漏一个标签）；dDurationMs 不可靠不使用；首项元数据给 T。

### parse_manual.py（人工·步骤1）
- **用法**：`python parse_manual.py <json3> <输出.jsonl> [--as-zh] [--auto]`（默认出 `{start,end,src}`；`--as-zh` 出 `{start,end,zh}`；`--auto` 对**自动字幕轨**（滚动式）先 cue 化——文本变化处切分、结束=下一状态开始）
- **目的**：cue 表（人工轨：start=tStartMs，end=tStartMs+dDurationMs，**零重算**；`--as-zh` 供规则①直用）；`--auto` 供"中源双语"的自动源语轨。
- **坑**：人工 cue≠完整句（多数无句末标点）→ 翻译前 AI 须合并整句、译文按原 cue 段数切回。

### filler_scan.py（语气词机械记账）
- **用法**：`python filler_scan.py <中间文件目录> [--keep 12,34] [--extra 56] [--write-dropped]`
- **目的**：把"已删语气词编号"从**手工记账**改成**元素表机械扫出**（手写编号容易整段错位、把内容词误删）。`--write-dropped` 直出 dropped.json；AI 只做 `--keep/--extra` 增删确认，**编号一律不手写**；`--extra` 登记的非标准丢弃会写进 notes 与 fillers_auto.json 留痕（机检③b 据此放行）。
- **坑**：只认"整元素"形态（词首词中的 uh 不碰）；机检③b 会反向校验"清单里每个编号必须真的是语气词（或已登记）"。

### bind_ids.py（机械绑定编号·核心）
- **用法**：`python bind_ids.py <中间文件目录> [--fix] [--show N]`（读 elements.json + dropped.json + lines_text 系列；`--fix` 写 lines_p1.jsonl）
- **目的**：**AI 只写文本（`lines_text_p*.jsonl`，`{src, zh}` 无编号），编号全部由本脚本产出**。原理：元素词流（剔除语气词，保留"词→元素编号"映射）与行文本词流做**全局单调对齐**（difflib，`autojunk=False`）——文本本就来自词流，对齐率天然接近 100%；`--fix` 落盘 `lines_p1.jsonl`（旧分片备份为 `prebind_lines_p*.jsonl`）；脚本按序号自动合并 `lines_text_p*.jsonl`（也支持读单个 `lines_text.jsonl`、或对已带 ids 的 `lines_p*.jsonl` 做校验模式）。
- **报表**：未覆盖元素（内容词漏了→回文本补词/或 `filler_scan --extra` 登记丢弃）、多余词（听写修正正常、真多写要改）；另有"提示"级机械兜底：**多词元素被切线切进内部→整体归词多的一侧（平手归前行）**、**纯符号元素→归相邻行**、**保留语气词词面/口吃重复→良性标注**；问题条目附上下文词（前后各 4 个，▸◂ 标出目标）。
- **`--show N`**：打印第 N 行绑定的区间元素 + 前后各 8 个（人工核对用）。
- **坑**：`autojunk` 必须关（默认把高频词当垃圾跳过，长列表上会毁掉对齐）；语气词必须先由 filler_scan 扫出（否则语气词挤进对齐、制造多余块）；切线落在多词元素内部必须做元素级归属（否则两行共占同一编号=重复归属）——已做整体归属兜底。

### report_progress.py（进度报点器·常驻一个）
- **用法**：`python report_progress.py <目录或文件> [--interval 5] [--stall 240] [--wait 15] [--slow-times 5] [--slow-kbps 100] [--done-file PATH] [--grow-stop SEC] [--total BYTES]`
- **目的**：把"观察下载/压制进度"从 **AI 自己 sleep 轮询** 变成**进度驱动的持续反馈**。挂成后台任务**跑到底**（不重挂），两条规则：**①每 5s（`--interval`）打一行进度**——已下 MB / 本段速率 / 平均速率 / 预计剩余，持续可见；**②完成或失败时主动打一行总结并退出**——退出即任务通知（通知机制里"退出"才是可送达的中断）：完成按 `--done-file`（推荐传成品文件路径）出现或监视目标消失判定；失败有两条——**停滞**（默认 240s 零增长）与**持续低速**（默认连续 5 次本段 <100 KB/s，疑似限速；`--slow-times 0` 可关）；**静止的成品文件**（非 `.part`）若在监视开始时已存在并持续 30s 无增长 → 按「✅ 已完成」报（不误报失败）。AI 收到退出通知后把进度与结果转述用户；中途目视**直接读它的输出**（非阻塞）。
- **目标可以还不存在**：下载器建 `.part` 有延迟——报点器启动时若找不到目标会**先等**（默认最多 `--wait` 15s，按节拍打印"等待目标文件出现…"），等不到才以"❌ 未出现"退出；**本技能下载流程给 `--wait 150`**（探测阶段需数十秒（元数据/选轨/字幕）才建 `.part`）。目录模式**优先盯正在写入的 `.part`**（复下进既有目录不被旧成品文件带偏）；**有 `--done-file` 且未出现时，静止的旧文件不会被当"已完成"**——等新 `.part` 出现后改盯。**压制场景**：目标给**输出文件路径** + `--grow-stop 15`（停增即完成）；别给目录（原片最大会被盯错）、别把 `--done-file` 指到输出文件本身（它会立刻误报完成；脚本遇同路径自动忽略并提示）。**"目标不存在"绝不能当"已完成"**（会把刚启动的下载误报成完成中断）。
- **坑**：三个时钟（全局/报告节拍/最后增长）必须各自独立——**报告节拍不得复位停滞时钟**；低速判定用**本段速率**且**只在见过增长后才计数**（否则"一开始就静止"会被误报成限速）；**目标一开始就有文件 ≠ 失败**（静止且非 .part 视为已完成）；`--total` 给了才有百分比/预计剩余；写临时名再改名的下载器会推迟"完成"判定。

### merge_shorts.py（短句合并）
- **用法**：`python merge_shorts.py <中间文件目录>`（读 lines_p*.jsonl + elements.json；写回 lines_p1.jsonl、备份 raw_*）
- **目的**：**保下限、应极少触发**——只有**整句（句义单元）行宽 < 4 字**才向后并（合并后行宽 ≤16 + 间隔 ≤1.5s；不级联）；合并原文字面压平为一行（**不机械折行**——折行是 AI 的活）。"让位于句义单元"由 AI 在切分环节负责。
- **坑**：备份用 `raw_` 前缀的**同目录文件**（不能匹配 `lines_p*.jsonl`，否则被 glob 误加载 → "编号重复"）；**目录名含 `[]` 时裸 glob 会静默写出空结果覆盖分片 → `glob.escape`**；现无分片文件时**报错退出、绝不写文件**。

### build_auto.py（打轴+输出+终检）
- **用法**：`python build_auto.py <「中间文件」目录> [--outdir 目录] [--name 基名] [--mode bilingual|zh|src] [--order zh-src|src-zh] [--preset default] [--font bundled|system] [--style-from <用户示例.ass>] [--gap 1500] [--subgap 0] [--vtt] [--srt]`（交付物自动出到 **一级目录**；`--outdir` 可覆盖；`--font system`=系统字体档供"不压制"；`--style-from`=采纳用户示例 ass 的字体/字号/颜色/描边）
- **目的**：打轴三条规则（N−L>g→M=L+g；否则 **M=N−间隔（默认 0ms，紧贴下一条）** 且 ≥L；末条 L+g 截 T）；输出 ASS（默认）+可选 VTT/SRT；机检（含 **③b 丢弃清单反向校验**："清单里每个编号必须真的是语气词（或在 `--extra` 里登记过）"；**④ 中文行宽 >16 报错——修复=重新分划、不许改译文凑行宽**；**⑤ 相似度 <0.6 报错**=src 大幅改写（→重跑 bind_ids --fix）、0.6~0.75 告警=轻微修正）；写 `<名称>.机检报告.md`（与产物同目录）。
- **坑**：格式校验前**必须先执行** strip（否则"写入时清了、校验用未清数据"会错报）；ASS 2 位百分秒取整到 10ms，比对用取整值；**机检重解析按"层号任意"匹配 `Dialogue: \d+,`（SRC=Layer1）**；**目录名含 `[]` 时裸 glob 会漏掉全部分片 → `glob.escape(mid)`**；无字幕行报错退出；`dropped.json` 缺失时按空处理并在报告里告警（不崩）。

### build_manual.py（人工收尾）
- **用法**：`python build_manual.py <「中间文件」目录> [--outdir 目录] [--name 基名] [--mode bilingual|zh|src] [--order zh-src|src-zh] [--preset default] [--vtt] [--srt] [--src-lines <源语轨.jsonl>]`（读该目录的 lines.jsonl；交付物自动出到一级）
- **`--src-lines` = 中源双语（原生两轨直出）**：lines.jsonl（中文轨 cue）+ 源语轨 cue 两个**独立事件流**（时间轴各自独立、不配对）；机检逐轨、跨轨重叠不报。
- **目的**：人工时间零重算输出+人工版机检（重叠**统计式**、中文允许 2 行）。
- **坑**：行尾标点清理必须**执行在先、校验在后**（只写校验会把未清理项一次性全报出来）。

### burn.py（压制/封装）
- **用法**：`python burn.py --video <视频> --ass <字幕.ass> --out <输出> [--mode hard|soft] [--hw auto|nvenc|none] [--codec auto|av1|hevc|h264] [--bitrate BITS] [--preset fast] [--crf 20] [--quality-first] [--fontsdir DIR] [--ffmpeg-args "<用户参数>"]`
- **目的**：硬字幕，**编码档 = AI 判断 + 脚本直跑**——AI 按硬件型号知识/现场查询决定并用 `--codec` 传入（NVIDIA 20/30 系→hevc、40/50 系→av1；拿不准不传）；**脚本不做任何探测**：**直接跑真实编码**（指定从该档、否则 AV1→HEVC→H.264），失败**逐级下退**；**最终 CPU 兜底只做 H.264**（libx264 fast/crf20，不压 AV1/HEVC）；**跨编码码率匹配**：目标码率 = 源码率 × 1.2 × EFF[出]/EFF[源]（EFF：h264 1.0/hevc 0.75/vp9 0.8/av1 0.7；禁固定倍率）；硬件档失败自动回退 CPU；音频 copy；**AV1/HEVC 兼容性要在选项表与交付时提醒**；压完打印体积对照）；软字幕（-c copy，mkv+ASS 保留样式，**默认随片附带字体附件**——输出软字幕即自动封装字体、无需用户要求；不附带则播放器回退错字体、样式走样）。
- **坑**：Windows 路径进滤镜转义不可靠 → 采用"ass+字体复制进临时目录、滤镜用相对路径"的免疫方案；mp4+opus 音频 → 转 AAC。

### preview_style.py（样式预览）
- **用法**：`python preview_style.py --video <视频> --out <预览.png> [--lines <lines.jsonl>] [--at 秒] [--preset default] [--fontsdir DIR] [--mode bilingual|zh|src] [--order zh-src|src-zh]`
- **目的**：给用户看"字幕在你自己视频上长什么样"。无字幕文件时用合成样例（一行中文+两行原文，顺带展示版面语义）；**`--mode zh|src` 可出"单中文/单外语"形态的预览**；`--order` 可切上下；取样时刻默认取该条中段。随技能**内置三张示意图**：`assets/style-preview-default.png`（双语）、`assets/style-preview-default-zh.png`（**单中文**）、`assets/style-preview-default-src.png`（单外语）——**开工时按用户所选形态给对应那张**（别拿双语图充数；交付物本身不带预览）。
- **坑**：与 burn.py 同一套临时目录免疫法；字体不对会静默回退——预览就是防这个的。

### setup_fonts.py（字体）
- **用法**：`python setup_fonts.py [--force] [--src-dir DIR]`（写 assets/fonts/PuHuiTi95.ttf + AlibabaSansBold.ttf）
- **目的**：生成 `assets/fonts/PuHuiTi95.ttf`（中文，族名 PuHuiTi-95）与 `AlibabaSansBold.ttf`（英文/原文，族名 AlibabaSans-Bold）——**两个 ttf 都要在 fontsdir 里**。
- **选型依据**：中文 95 ExtraBold——与 55 字集逐字完全一致（29,296 字形 / 29,197 码位、主区 CJK 20,976），真字重；105/115 小字符集不能用；L3 不可用（缺字回退落系统字体、合单文件超 TrueType 上限 65,535）。英文 Alibaba Sans **Bold**——700 字重、ASCII/Latin-1/西里尔全、无 CJK。
- **来源**：本机字体目录（含 Downloads 官方解包）→ 官方 zip（两个：`AlibabaPuHuiTi-3.zip` / `AlibabaSans.zip`，**均须带 `Referer: https://fonts.alibabadesign.com/`**，否则 403）。
- **坑**：两套字体全字重**共用族名**（`Alibaba PuHuiTi 3.0` / `Alibaba Sans`）→ 不改名必选错字重；改族名只动 name 表 id 1/4/16/6、字形不动；Sans 的 zip 里含 `__MACOSX` 垃圾项要跳过。

### cookies/（Cookie）
- **用法**：`node get_cookies.js <浏览器> out.json [--profile Default --user-data-dir "<User Data 根目录>"]` → `python json2cookies.py <in.json> <out.txt>`
- **get_cookies.js**：playwright-core 无头启动浏览器（名称认不出的浏览器给 **exe 路径 + `--user-data-dir`**；须先关闭浏览器、profile 不被占用）→ `ctx.cookies()` → Cookie-Editor JSON；**启动超时默认 30s（`--timeout MS` 可调）——超时/失败即视为「自动获取做不到」，转请用户直接提供 cookie 文件**；找不到 playwright-core 时按其提示 `npm init -y && npm install playwright-core`。
- **json2cookies.py**：兼容 Cookie-Editor 与 playwright 原始格式 → Netscape；值内换行/制表符必须先剔除。

## 三、assets 与外围文件的搭建（示意素材 / 字体 / 秘密目录）

- **样式示意图（assets/ 三张，随技能分发）**——由 `preview_style.py` 渲染，合成背景 + 合成样例（1 行中文 + 2 行原文）。复建命令（在本技能根目录执行）：
  ```bash
  # ① 合成背景（深蓝渐变、1080p、4 秒，够 --at 3 秒取样）
  ffmpeg -y -f lavfi -i "gradients=s=1920x1080:c0=0x1b2a41:c1=0x0b1017:d=4:r=30" -c:v libx264 -pix_fmt yuv420p bg.mp4
  # ② 三种形态各渲一张（分别对应字幕形式三态）
  python scripts/preview_style.py --video bg.mp4 --mode bilingual --out assets/style-preview-default.png
  python scripts/preview_style.py --video bg.mp4 --mode zh        --out assets/style-preview-default-zh.png
  python scripts/preview_style.py --video bg.mp4 --mode src       --out assets/style-preview-default-src.png
  ```
  验收：三张分别呈现 双语 / 只有中文行 / 只有原文行；**目视字体命中**（普惠体真字重 + Alibaba Sans，字体不对会静默回退）；渲染用的 ASS 与正式输出共用 `sub_style`——预览什么样、压出来就什么样。
- **字体（assets/fonts/ 两个 ttf）**：`python scripts/setup_fonts.py` 生成（族名副本、字形不动）；缺失会导致静默回退、必查；来源与选型依据见下方 setup_fonts.py 条目。
- **secrets/**：只放 `README.md`；cookie 属于使用者本人、运行时现场获取——**随技能分发时必须为空**。
- assets/ 下没有其他素材（就 fonts/ 与上述三张图）。

## 四、重建验收（冒烟最小集）

```bash
python -m py_compile scripts/*.py scripts/cookies/*.py && node --check scripts/cookies/get_cookies.js
# 风格冒烟：任取一条 lines.jsonl（含 start/end/zh/src）——输出放一个临时子目录
mkdir -p _smoke
python scripts/sub_style.py <lines.jsonl> _smoke/smoke.ass            # 生成 ASS
python scripts/burn.py --video <视频> --ass _smoke/smoke.ass --out _smoke/smoke.mp4
python scripts/preview_style.py --video <视频> --out _smoke/prev.png  # 合成样例预览
```
验收标准：ASS 时间戳 2 位百分秒、字体命中（预览图目视）、压制产出可播放且时长与源一致。

> **路径注意（Windows + Git Bash）**：调用 Python / ffmpeg 时**一律用相对路径或 Windows 风格路径**——
> Git Bash 的 `/tmp`、`/c/...` 这类 MSYS 虚拟路径，原生 Windows 程序不认（`/tmp/x` 会被解释成
> `C:\tmp\x`，多半不存在而报错）；**且带 `[ ]` 的参数 Git Bash 根本不会自动转换**（本技能项目文件夹名固定带 `[]`）——**一律写 `C:/…` 或相对路径**；`report_progress.py` 已内置 `/c/…` 兜底转换（其他脚本没有）。脚本内部自己用的是 Python `tempfile`，不受影响。
