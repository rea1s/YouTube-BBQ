# YouTube 字幕翻译技能 · 设计规则

> 全流程规则总表：初始化 / 下载 / 自动字幕 / 人工字幕 / 字幕格式 / 压制 / 执行要求。
> 与 `scripts/` 一一对应；改动前先与用户讨论。

---

## 〇、总原则

- **按下按钮得结果**：全自动，**用户明确确认选项表之后才算"按下按钮"**、之后不再打断用户；需要用户拿主意的部分（参数、**是否先出字幕确认再压制**）在**这个确认环节一次性定死**。
- **异常不中断**：轻微错误→轻微修正；错误过大→译文保留原词；异常随手记入"小本本"；全部完成后交报告。
- **过程全落盘**：每一步都有中间文件，可检查、可续跑。
- **时间只用整数毫秒**流转，写文件时才格式化（VTT/SRT 恰好 3 位小数、ASS 恰好 2 位），写完自动校验。

## 一、初始化

### 1.1 依赖

| 组件 | 用途 | 说明 |
|---|---|---|
| yt-dlp | 下载视频/字幕 | pip 安装（已知可用版本：2026.08.19） |
| yt-dlp-ejs | 解 YouTube JS 签名/n challenge | **必需**，缺失报 signature/n challenge 失败 |
| curl-cffi | 请求 impersonation | **必需**，缺失触发 403 "Only images available" |
| node | yt-dlp-ejs 的 JS 运行时 | 调用时加 `--js-runtimes node` |
| ffmpeg（带 libass） | 音视频合并、字幕压制 | 8.1 |

安装：`pip install yt-dlp yt-dlp-ejs curl-cffi`；`node` 与 `ffmpeg` 随系统安装——**ffmpeg 必须带 libass**（验证：`ffmpeg -filters | grep ' ass '` 有输出，或 `ffmpeg -version` 的配置含 `--enable-libass`），否则字幕烧录会失败；**字体与样式示意图已随技能自带**，无需额外下载。

### 1.2 网络（代理）

- YouTube 直连不通，**必须走代理**。
- **模式（前置选项）**：默认**外部代理**（自动探测常见端口，7897 优先）——使用前**提醒用户确认自己的代理在运行**；保留"使用内部代理"选项（走环境注入的隧道）。
- 外部代理模式下调用 yt-dlp 前清空 `*_PROXY` 类环境变量（防止隧道劫持），显式 `--proxy` 指定。

### 1.3 Cookie

- 默认读取本地 cookie 文件（Netscape 格式）。
- 获取方式（按优先级）：
  1. **CDP 自动提取**：无头启动本机安装的浏览器（内置 Edge / Chrome 常见安装路径；其他浏览器——如便携版——传可执行文件路径 + `--user-data-dir`），由浏览器自身解密后经 CDP 读出 cookie；
  2. 浏览器扩展导出 JSON → 转换 Netscape。
- **Cookie 是前置必做项（在前置检查阶段完成）**，不属于「给用户的可选项清单」；**交互顺序固定为「先教用户 → 再自动获取 → 失败才要文件」**：
  ① 检查 `secrets/cookies.txt`；没有就先告诉用户三步：**在浏览器登录 YouTube** → **告知浏览器名称（认不出就给 exe 路径）** → **关闭该浏览器**（关闭后回复）；
  ② 用户回复后**自动获取，超时 30s**（`get_cookies.js ... [--timeout MS]`；开着浏览器会读到空 cookie/启动失败）；
  ③ **失败或超时 → 再请用户直接提供 cookie 文件**（Netscape 格式，给路径即可，`--cookies <路径>` 指定）。
  带 cookie 可降低限流、访问年龄限制/会员内容；用户始终无法提供时停下说明，不跳过。

### 1.4 环境自检

启动时检查**依赖 / 代理 / Cookie** 可用性，输出状态；缺什么补什么（Cookie 缺失即按 §1.3 现场获取）。

## 二、下载

### 2.1 选轨（三级规则）

场景锁定「**外文 → 中文**」：

1. 有人工**简体中文**轨（zh-Hans / zh-CN / zh）→ **直接用，不翻译**；同时探测人工**源语言**轨——有则记入 decision.json 的 `track_src` 并**两轨一起下载**（用户选双语形态时走"中源双语：原生两轨直出"，见 §4.3）；
2. 否则取人工字幕里的**源语言**轨 → 翻译；
3. 无人工字幕 → 取自动字幕的**源语言**轨（`-orig`；多个 `-orig` 时用 `info['language']` 消歧；仍不唯一由 AI 判断）→ 翻译。
- **强制指定字幕轨**：支持，但是**隐藏项**——不进选项清单，由用户与 AI 临场交流处理。

### 2.2 视频

- **画质是交互项**：① 用户指定了档位 → 按用户来；② 未指定 → 默认 **1080p60**。**探测后先检查可用性**：该档位（含帧率——帧率按"不低于"理解）在视频里**不存在** → 脚本以 **`[需决策]` 退出**并列出可用画质，**AI 必须把列表交给用户确认要哪一档，再用 `--quality <档位>` 重跑**（不擅自换档、不静默降级）；③ 档位存在 → 按用户指定**封顶**：格式选择器对每个下载方式都带 `[height<=H]`，排序 `res:H[,fps:F],vcodec:<偏好>,acodec:aac`（偏好默认 av1、**HLS 路径为 vp9**）——**指定 720p 绝不会下 1080p**。
- `--quality` 支持：`best`（不封顶）/ `2160p`、`1440p`、`1080p60`、`1080p`、`720p60`、`720p`、`480p`、`360p`（数字可省 `p`、可带帧率），别名 `4k/2k/8k/hd/fhd`；**认不出的写法直接报错**（不再静默回退默认画质）。
- **下载后校验（安全网）**：实际高度必须 **≤ 上限** 才算达标；超标即判为选择器失效、删除重试（正常流程下"档位不存在"已在探测阶段被 `[需决策]` 拦下）。
- **片源编码 / 下载方式**：YouTube 只提供三种编码——**AV1 / VP9 / H.264**。**默认走 HLS 分片下载（`-N 8` 并发）→ 实得 VP9**（HLS 无 AV1 轨；也是最稳的方式）；**备用序：默认客户端 → web_embedded**（这两条是 DASH 客户端路径，可拿 AV1）。`--vcodec av1|vp9|h264|any` 可指定——**明确 av1 时自动改走 DASH 客户端优先**；音频优先 **m4a/AAC**（mp4 兼容）。注意：**AV1/VP9 在个别播放器、剪辑软件上解码支持不足**（切 h264 即可）。
- `--merge-output-format mp4`；默认质量 `1080p60`。
- **"只要字幕并翻译"开关（前置选项）**：开启时不下视频，只下字幕并翻译。
- 产物保留原视频；**重复下载不覆盖已存在文件——新文件自动加 `(2)` 后缀**。

### 2.3 字幕

- 格式：**json3**（唯一带词级时间戳的格式）；`--write-auto-subs --sub-langs <选定轨> --sub-format json3`。

### 2.4 目录与产物

- 每个视频一个**视频名称文件夹**，名称**默认 `[制作者]视频标题-YouTube`**（非法字符替换）；**可选**：用**翻译后的标题**命名（默认否）；取不到标题时用视频 ID。**两级结构：一级只放交付物；一切中间/过程文件放二级 `中间文件/`**：

```
<视频名称>/                     # 一级：只放交付物（源视频 / 压制版 / 字幕 / 报告）
├── <名称>.mp4            # 源视频
├── <名称>.hardsub.mp4    # 硬字幕压制版（**默认输出**）
├── <名称>.softsub.mkv    # 软字幕版（可选，默认不输出；视频流零重编码，**随片封装字体**）
├── <名称>.ass            # 字幕文件（默认 ASS；可选 .vtt/.srt）
├── <名称>.报告.md        # 处理报告
├── <名称>.机检报告.md     # 机检报告
└── 中间文件/              # 二级：**其余一切**（过程文件；脚本传入的「目录」默认指这里）
    ├── <名称>.json3 / decision.json / probe.json
    ├── elements.json / stream.txt / dropped.json / fillers_auto.json
    └── lines_text_p*.jsonl / lines_p*.jsonl / prebind_* / raw_* / cues.json
```

- **批量**：无需专门开关——由 AI 按请求理解（多个链接/播放列表即批量）；在视频名称文件夹**上层再套一层**批量文件夹（名称取播放列表名或用户指定）；**汇总报告放在最外层（批量）文件夹内**。

### 2.5 已知坑

- 格式提取存在**瞬时 403**（"Only images available"）→ 下载环节内建重试；
- 少数视频字幕轨受 **PO token** 限制取不到（记入报告、换轨/跳过）；
- 自动配音视频会出现多个 `-orig`（每个配音音轨一个），靠视频语言字段定位真原始轨；个别视频没有源语言 ASR 轨（记入报告）；
- **媒体流 403 的下载方式优先级**：YouTube 对默认客户端强制 SABR/PO Token 时，元数据/字幕仍可下、媒体流下几十 MB 即 403。依序尝试：
  ① **HLS 分片**（默认；`protocol*=m3u8`，hlsnative 每片独立请求 + **`-N 8` 并发**——最稳；无 AV1 轨，实得 VP9）；
  ② 默认客户端（DASH，可出 AV1）；
  ③ `--extractor-args "youtube:player_client=web_embedded"`（免 token 客户端；**注意多轮进程续传可能把流切坏**，必须全片解码校验）；
  三种都不行 → 报告用户，建议稍后重试或更换网络/代理；**不用第三方下载站**（下载环节弹广告、要人机验证，流程不可靠）。

## 三、自动字幕处理流水线

> 输入：下载到的 json3 自动字幕轨；输出：可播放/可压制的字幕。
> 所有"语言活"由 AI 完成，脚本只做确定性搬运。**编号全部由脚本产出，AI 不写任何编号。**

### 步骤 1 · 解析与机械化去噪（`parse_json3.py`）

- 元素绝对时间 = 事件 `tStartMs` + seg `tOffsetMs`（缺省 0，即事件首个 seg 无偏移）。
- 按事件顺序、事件内按 seg 顺序遍历所有文本元素 → 扁平**三列表**：`编号 | 绝对时间(ms) | 元素文本`。
- 机械化去噪，只删三类，不做其他判断：
  1. 换行符 `\n`（含"收条"事件整体丢弃）；
  2. `[...]` 包裹的提示（整元素形态删）；
  3. `>>` / `>>>` 说话人标记（整元素形态删；粘连词首则剥掉符号保留文本）。
- **去噪后连续编号**（0,1,2,… 无空洞）；元素文本保留原样（含前导空格）。
- 产出：`elements.json`（元素表）+ `stream.txt`——**供 AI 阅读的纯词流：无编号、每行 12 个词**
  （编号只活在机器侧与报表里；每行 12 词的结构供 AI 按行分块/续跑）。

### 步骤 2 · 语气词机械记账（`filler_scan.py`）

- **语气词编号一律由元素表机械扫出，不许手写**（手写编号容易整段错位、把内容词误删）。本步骤先于 AI 写作执行。
- 只认"整元素"形态的语气词；`--write-dropped` 直出 `dropped.json`；AI 只做增删确认：
  - 故意保留的候选 → `--keep`；
  - 候选之外确要丢弃的词（如 "you know"）→ `--extra <编号>` **登记留痕**（写进 notes 与 `fillers_auto.json`，机检③b 据此放行）。
- AI 写文本时**不写语气词**；引语里刻意保留的语气词词面会被绑定报表标"提示"（正常）。
- **结巴重复词保留**（"我我我"、"the the"）。

### 步骤 3 · 分句、翻译与切行（AI，只写文本，一遍完成）

- **输入** `stream.txt`（纯词流），**输出纯文本**：`lines_text_p*.jsonl`，**不带编号**——对应关系由步骤 4 机械绑定。
  格式（每行一条，`src` 忠实拼接、`zh` 译文）：
  ```json
  {"src": "This fight took me three tries", "zh": "这场架我打了三次"}
  {"src": "and the boss still had a second phase", "zh": "结果 Boss 还有二阶段"}
  ```
- **分句**：断句靠语义（标点不可靠：有无标点取决于视频而非语言）；AI 自行**补空格、补标点**，修复跨事件粘连。
- **切行**（一条字幕 = 一个显示单位）：
  - 译文行宽**最优 10 字、硬上限 16 字**（切行尽量落在 10 字附近）；断点优先取标点与语义停顿，仍超长按词组边界继续切。
  - **行宽计法**：汉字与标点各占 1（书名号、逗号各 1；破折号 `——` 按 2）；**只豁免行尾那一个 ，。,. **；
    译文里的英文/数字每 2 个算 1、空格 0.5——以 `sub_style.zh_len` 为准。
  - **超限的修复动作 = 重新分划**：机检报中文 >16 时，回文本层**重新切分**（拆成两条 → 重绑 → 时间轴机械重配）；
    **不得通过修改译文（增删字词）来消除超限**——行宽是"切在哪"的指标、不是"怎么写"的指标；
    "为行宽改译文"与"为凑字数去并句"同属禁止项。
  - **短句合并（保下限，应极少用）**：判断单位 = **句义单元**（"一句话"——逗号划分的也算一句）；
    **只有整个句义单元行宽 < 4 字**时才考虑与相邻字幕向后并（合并后 ≤16 + 间隔 ≤1.5s；不级联，每条最多向后并一次）；
    **句义单元 ≥4 字一律不并**——不为了凑字数去并。机械兜底：`merge_shorts.py` 按同条件执行。
  - **原文（src）**：不设独立长度上限，跟随中文容量；过长可显示 **2 行**（约 45 字符处断一次，**由 AI 在词组/词边界断**——
    脚本不代劳、避免词内断行；脚本只校验"行数 ≤2"）。
- **`src` 忠实性（硬规则）**：每条 `src` 必须与其绑定的元素区间是**忠实拼接**关系——书写层规整可以
  （空格/标点/大小写/听写修正）；**不得删词缩句**。不忠实会在绑定报表里以"未覆盖元素/多余词"逐条报出（见步骤 4）；
  机检⑤（<0.6 报错）是最后一道闸。修复手法 = 回**文本层**改（补词/修措辞），**永远不改编号**。
- **翻译**：忠于原意、不增不减；口语化、符合中文表达习惯；结巴原文保留但译文求通顺；数字单位按中文习惯。
  **人名/专名一律译成中文**（人名音译、专名意译或通用译名）；**仅"中文语境也用英文"的词保留原文**（品牌/通用术语，
  如 PlayStation、Boss、State of Play）；作品名加《》；**全文一致**（开工先定**术语/译名表**，各分块沿用）；
  听写不确定的词保留原词并记入报告。
- **自检（不中断流程）**：轻微错误（听错、拼写、漏字）可轻微修正；错误过大、无法确定原意 → **译文保留原词**；
  全部异常记入"小本本"，最后随报告提交。
- **形态**：中文 1 行 + 原文最多 2 行；**末尾标点清理**（中文「，。」与原文「, .」两侧都执行，其他标点不动）。
- **双语对照**：尽量一一对照；一条"一句"仍需再切且两边语序不同时：**中文先按规则切好**，
  原文按「长度比例优先 + 语义断点」切成与中文**相同的条数**，然后顺序 1:1 对应。
- 注意多讲述人/背景音：仅留意不混句，**不做标注**。

### 步骤 4 · 机械绑定编号（`bind_ids.py`）

- **编号全部由脚本产出**（AI 一个都不写）：`python scripts/bind_ids.py "<目录>"`（只报告）→ 报表干净后 `--fix`
  落盘 `lines_p1.jsonl`（绑定前备份 `prebind_lines_p*.jsonl`）；脚本按序号自动合并 `lines_text_p*.jsonl`。
- 原理：元素词流（剔除语气词、保留"词→元素编号"映射）与行文本词流做**全局单调对齐**
  （difflib `SequenceMatcher`、`autojunk=False`）——文本本就来自词流，对齐率天然接近 100%。
- **报表三类**（问题条目带**上下文词**：前后各 4 个、▸◂ 标出目标——文本无编号，按上下文搜定位）：
  1. **未覆盖元素**：内容词没进任何行 → 回文本层**补词**；确属冗余词要丢弃 → `filler_scan.py --extra <编号>` 登记后重跑；
  2. **多余词**：听写修正（替换块）属正常；真·多写要改文本；
  3. **提示（可忽略）**：多词元素被切线切进内部（脚本已整体归词多的一侧、平手归前行）、纯符号元素归相邻行、
     保留语气词词面、口吃重复词——都是机械兜底。
  报表样式（示意）：
  ```
  行数 336｜对齐率 99.9%（equal 3148 / replace 1）
  [注意] 1 个元素未被任何行覆盖（内容词漏掉？前 15；▸◂ 为目标词）：
     [1234] really ｜ and like ▸really◂ explore different
  [提示] 1 处口吃/重复词（良性）：[(128, 'like')]
  ```
- **切线不必看元素边界**：AI 按语言切；落在多词元素内部由脚本兜底（AI 只管语言，机械的事脚本做）。
- 覆盖要求：除被删语气词外，全部元素必须落到某条文本里（漏了会以"未覆盖元素"逐条报出）。

### 步骤 5 · 打轴与输出（`build_auto.py`）

- 记号：**M** = 本条结束时间，**N** = 下一条开始时间，**L** = 本条末元素开始时间；本条**开始时间 = 首元素开始时间**（查元素表）。
- 规则：
  1. **长停顿**（N − L > 1.5s）→ M = L + 1.5s；
  2. **正常衔接**（N − L ≤ 1.5s）→ **M = N − 间隔**（**默认间隔 0ms：本条显示到下一条出现，紧贴**）；
     **硬约束 M ≥ L**（仅自定义间隔 >0 时才可能触发，触及时取 M = N）；
  3. **末条**（无下一条）→ M = L + 1.5s；超出总时长 T 截到 T。
- **零重合是原则**：任何情况下两条字幕时间不重叠。
- 输出 ASS（默认）+ 可选 VTT/SRT + 全量机检（见终检①）；T 来源：自动字幕元数据首项 `dDurationMs`。

### 终检（全部完成后执行）

**① 机器校验**（脚本自动、逐条硬性）：

1. **打轴全量重算**：用元素表 + 参数重算所有 M/N/L，与产出逐条比对，必须 100% 一致；
2. **零重合**：每条 M ≤ 下一条开始时间、且 M ≥ L；编号顺序正确；
3. **编号完整性**：编号并集全覆盖；字幕间空洞 ⊆ 已删语气词编号；无重复归属；
   **③b 反向校验**：丢弃清单里每个编号在元素表里**必须真的是语气词**（或在 `fillers_auto.json` 的 `extra` 里登记过），
   否则报错——抓"差一位/错删内容词"；
4. **格式规则**：时间戳小数位（VTT/SRT 恰好 3、ASS 恰好 2）；中文恰好 1 行、原文 ≤ 2 行；
   中文**行宽 ≤16**（>16 报错、<4 告警；计法见步骤 3；**>16 的修复=重新分划，不许改译文凑行宽**）；
   中文行尾无「，。」、原文行尾无「, .」；
5. **原文—编号一致性**：每条字幕原文片段与其编号区间元素文本做归一化相似度比对——**<0.6 报错**
   （通常是某行 src 被大幅改写 → 重跑 `bind_ids.py --fix`；`--show N` 看单行明细）、**0.6~0.75 告警**（轻微修正的正常痕迹）。

**② AI 终读**：通读成品——中文连贯性、错漏译、术语一致性、双语行对应；发现问题回对应块修正。

**③ 交付清点**：字幕文件 + 视频（如有）+ 压制版（如有）+ 报告 + 小本本。

失败处置：能重算修正的自动修（时间轴全可重算）、文本类回块修、修不了的写入报告——不打断用户。

### 执行方式与过程文件

- **AI 语言工作：逐块循环「读→想→写→查」**：每块约 **85~100 行**（`stream.txt` 每行 12 个词，≈1000~1200 个词）；
  **块尾多读约 10 行、切点落在句子边界**；本块内一遍完成分句+翻译+切行并写 `lines_text_pN.jsonl`
  （追加落盘、按行号续跑）；**写完立刻跑 `bind_ids.py` 看报表、本块问题当场修**（上下文还热）；
  全部写完才 `--fix`。**跨块一致性**：① 术语/译名表首块建立、后续沿用；② 块间接续——
  上块结尾句子未完就自然续到下块开头（不硬拆、不硬并）。
- **分块照旧，由主 agent 串行翻译**：每块 85~100 行（≈1000~1200 词）按行号切；主 agent 按「读→想→写→查」**逐块串行**完成（一致性最好）；**仅当视频时长 > 60 分钟**时，开工后（探测得到时长，取自 decision.json 的 duration）**询问用户**是否改用**子智能体并行**（各子代理分一块；术语表由主线统一下发、靠终读兜一致性）——用户未选则保持串行。
  思考保持开启（中档即可）——提速靠分块与（可选）并行，不靠关思考。
- **下载与字幕并行**：先下字幕（同时=**连通性自检**）→ 视频下载用**后台任务**跑（完成/失败以**任务通知**形成"中断"，
  不用"自己 sleep 再看一眼"的轮询）→ 中途进度交给**报点器**：
  挂**一个** `report_progress.py "<目录>" --interval 5 --done-file "<目录>/<名称>.mp4"` 跑到底——
  规则①每 5s 报一行进度；规则②完成/失败主动总结并退出（退出=中断；完成=成品文件出现；
  失败=停滞默认 240s 零增长 **或持续低速：默认连续 5 次本段 <100KB/s，疑似限速**）；
  **目标文件尚未出现也能挂**（会自动等待——**下载流程给 `--wait 150`**：探测阶段需数十秒（元数据/选轨/字幕）才建 `.part`，默认 15s 会误报"未出现"；"不存在"不等于"已完成"）；目录模式下**优先盯正在写入的 `.part`**（复下进既有目录不被旧成品带偏）；**有 `--done-file` 时旧静止文件不会被误判「已完成」**（会等新 `.part` 出现并改盯）；无 `--done-file` 且开始时已有静止成品 → 30s 内报「已完成」（低速判定只在见过增长后才计数，静止不算低速）；
  AI 收到退出通知转述用户，中途目视直接读它输出（非阻塞）。**等待都在后台任务里，AI 自己不 sleep、严禁固定长 sleep**；
  同时开始字幕处理，每处理完一块顺手看一眼进度。**压制同理**（后台任务 + 报点器）：**报点器目标给输出文件路径、用 `--grow-stop 15` 判完成**——输出文件从第一秒就在写，故**不要给目录**（原片最大会被盯错）、**不要把 `--done-file` 指到输出文件本身**（「出现」≠「完成」会立刻误报；脚本遇同路径会自动忽略并提示）；完成以 burn 任务退出通知或停增 15s 为准。成片体积/码率异常偏大时告知用户。
- 过程文件与产物位置（**两级结构**：一级只放交付物，中间文件全在 `<项目目录>/中间文件/`——parse/filler/bind/merge/build 各脚本传入的「目录」都指这个二级目录；build_* 的 `.ass` 与机检报告会自动出到一级）：原片 `<名称>.mp4`；字幕 `<名称>.ass`；
  硬字幕 `<名称>.hardsub.mp4`（如启用）；软字幕 `<名称>.softsub.mkv`（如启用）；报告 `<名称>.报告.md`；
  机检报告 `<名称>.机检报告.md`；过程文件 `elements.json` / `stream.txt` / `lines_text_p*.jsonl`（AI 纯文本）/
  `lines_p*.jsonl`（绑定产物；绑定前备份 `prebind_lines_p*.jsonl`）/ `dropped.json` / `fillers_auto.json` /
  `decision.json` / `probe.json` / `cues.json` / `<名称>.json3`（合并在前的分片备份 `raw_lines_p*.jsonl`）。

## 四、人工字幕处理

> 适用：下载选轨命中"人工字幕"的情形（规则①人工简体中文直用 / 规则②人工外文轨翻译）。
> 总原则：**尊重人工成果**——人工的切行与时间轴是做好的，不重切、不重新打轴；AI 只做语言活。

### 4.1 输入格式（与自动字幕的差异）

- 事件 = **一条显示字幕**（人工已切好行，多为从句/短语片段，**不等于完整句子**）；每个事件带 start 和时长（可靠）；
- 有标点；**无**词级 segs（无 tOffsetMs）、**无**收条事件、**无**元数据首项（**没有 T**）；
- cue 文本内可含换行（**两行显示是常态**）；相邻事件零重叠（时间干净）。

### 4.2 总流程（与自动字幕同一目标输出）

```
① 脚本  解析 → cue 编号表（编号 / start / end / 原文），完整保留人工时间
② AI    合并整句（人工版"分句"）：末尾无句末标点的事件与后续合并为一句
③ AI    逐句翻译（规则与自动完全一致：忠实、口语化、人名专名译中文、自检不中断）
④ AI    切分重排：把译文切回原 cue 的段数，与 cue 一一对应、顺序对应
⑤ 脚本  输出（时间 = 人工 start/end，零重算）+ 终检
```

### 4.3 情形①：人工简体中文轨 → 直接用

- **不翻译、不合并、不切分、不重打轴**：解析 → 机械清理（空 cue、`[tag]`/`>>` 若遇到）→ 呈现层统一（末尾「，。」删除；**保留人工换行**，≤2 行）→ 输出单语中文（VTT/SRT/ASS）→ 终检。
- 开头署名行（"翻译人员：…"）默认**保留**（那是译者署名），报告中提示可删。
- 只存在人工**繁体**轨时不命中①：按②处理（译成简体），情况写入报告。
- **中源双语（原生两轨直出）**：人工**简体中文轨**与人工**源语言轨**都在时，双语形态 = **两轨原样直出**——中文轨（ZH 样式、Layer 0）+ 源语轨（SRC 样式、Layer 1），输出同一 ASS 的**两个事件流**；**两条时间轴各自独立**（不配对、不对齐、不套 M/N/L、不做间隔调整、不合并；两轨同时显示/边界错开是常态）。输出走 `build_manual.py --src-lines`（见 SKILL §五 B-①b）；跨轨"重叠"不视为问题、不报警。
- **无人工源语轨 → 自动源语轨补原文行**：原文行取 `-orig` 自动轨（**独立时间轴**；ASR 文本、听写误差记入报告）；自动轨是滚动式 json3，解析时先 cue 化（`parse_manual.py --auto`）。**连自动源语轨也没有** → 双语不可用：按单中文直出、情况写入报告。

### 4.4 情形②：人工外文轨 → 翻译

- 翻译规则与自动字幕**完全一致**（人名/专名译中文、小本本、自检不中断）。
- **切分重排特殊规则**：译文切成**与原文 cue 相同的段数**（英文 cue ≈ 40 字符 ↔ 中文段 ≈10 字，行宽计法同自动；上限 16）；语序对不上时用与自动相同的"长度比例优先 + 语义断点、顺序对应"；长度是**软目标**（以还原人工节奏为先，不强求下限）。
- **打轴 = 零重算**：每条字幕时间 = 对应 cue 的 start/end（人工值原样；不套 M/N/L、不截断、不合并）。
- 单句实在压不进原段数（罕见）→ 该条中文允许折 2 行（同一条内显示），记入报告。
- 双语形态与自动一致：中文行 + 原文行（原文取 cue 文本，保留其换行、≤2 行）。

### 4.5 终检（人工版）

- **机器**：时间戳格式与非负；中文 ≤2 行、原文 ≤2 行；末尾标点清理确认；**零重合检查（统计式——人工字幕若有重叠，报告但不强修）**；额外查"每个 cue 都有译文"（全覆盖）。
- **中源双语（双轨）时**：以上检查**按轨各查一遍**；**不做配对/覆盖检查、跨轨重叠不报**（两轨本就同时显示）。
- **不做**：M/N/L 重算、行宽上限（16）硬校验、短句合并（人工切分不动）。
- **AI 终读**：同自动（连贯、错漏译、术语一致、双语对应）。

### 4.6 执行方式

体量小（约每 5 分钟 80 条 cue）：通常一趟完成；长片按约 300 条 cue 分块。产物与自动一致（cue 表 / 字幕行 JSONL / 打轴产物 / 小本本 / 报告）。

## 五、字幕格式

### 5.1 输出格式与字幕形式

- **字幕文件默认只出 ASS**（时间戳恰好 2 位百分秒 `H:MM:SS.cc`）；**VTT / SRT 为可选项**（3 位毫秒；VTT 点号、SRT 逗号）。
- **字幕形式三态（前置选项）**：① **双语（默认）**——默认上中下外（中文在上），**上下顺序可切换**；② **只外语**（只出原文行，无需翻译）；③ **只中文**（只出译文行）。

### 5.2 双语版面（双固定水平）

- **中文**：**底部锚定**（Alignment=2，MarginV 从屏幕底计）→ 永远同一水平；
- **原文**：**首行顶部锚定**（Alignment=8，MarginV 从屏幕顶计）→ 首行永远同一水平，第二行自然往下；
- 基准 PlayRes 1920×1080（其他分辨率由 libass 等比缩放）。

### 5.3 样式参数（1080p 基准，默认款）

（样式以**预设**形式提供，配**内置示意图**：双语 `assets/style-preview-default.png`、**单中文 `style-preview-default-zh.png`**、单外语 `style-preview-default-src.png`——开工时按用户所选形态把对应那张链接给用户确认；也可用待处理视频的样例帧现渲染。）

| 元素 | 字体 | 字号 | 颜色 | 描边 | 定位 |
|---|---|---|---|---|---|
| 中文 | 阿里巴巴普惠体 **95 ExtraBold**（真字重，不用 Bold 假粗） | **82** | 白 `&H00FFFFFF` | 黑 `&H00101010`，**2.0** | 底距 **121px**（Alignment=2；单中文形态 **80px**） |
| 原文 | **Alibaba Sans Bold**（阿里配套拉丁字体，Bold 字重） | **62** | `&H00E8E8E8` | 黑 `&H00101010`，**1.2** | 首行顶距 **950px**（Alignment=8；单原文形态**底部锚定**、底距 **80px**） |

- 中英墨迹间距 **22px**；描边 2.0 / 1.2。
- **两个单语形态各有专用边距**（`sub_style.PRESETS['default']` 的 `zh_only_mv` / `src_only_mv`，均 80）：
  单中文 = 中文底距 80（Alignment=2）；单原文 = 原文行**底部锚定**、底距 80（Alignment=2，多行时整块贴底）。
- **层约定（关键实现）**：**SRC 事件一律 Layer 1、ZH 一律 Layer 0**——libass 的"防重叠"会把**同层**相邻槽位钉住（边距改了位置不动）；分层后位置 100% 听边距，顺带消除"边距交叉导致上下顺序颠倒"的隐患。`build_auto` 机检重解析 ASS 按"层号任意"匹配；
- （注：原文两行时第二行墨迹距屏幕底约剩 **12px**（1080p 基准；含 d/y/p 类下伸字母），后续再调字号/位置需留意余量）

### 5.4 字体随行（重要实现）

- **字体获取**：官方直链（**均须带 `Referer: https://fonts.alibabadesign.com/`**，否则 403 "denied by Referer ACL"）——中文 **`AlibabaPuHuiTi-3.zip`**（约 266MB）/ 拉丁 **`AlibabaSans.zip`**（约 1.6MB）；本机已装也可直接取本机文件；
- **中文字集选型**：**95 ExtraBold 与 55 Regular 字集逐字完全一致**（29,296 字形 / 29,197 码位、主区 CJK 20,976）→ 中文用 95 = 真字重（不用 Bold 假粗）；105/115 是小字符集（约 9.6 千码位）不可用；**L3 大字符集不可用**——L3 只含康熙部首 + 6 万扩展平面 CJK（连 ASCII 都没有），**libass 缺字回退不认 fontsdir 里的 L3、会落系统字体**（尺寸/字重不一致），且与 95 合并成单文件不可能（89,634 字形 > TrueType 硬上限 65,535）；译文为中文、本身不会有生僻字——所以中文直接用 95 单字集；
- **英文字体**：**Alibaba Sans Bold**——阿里设计配套的拉丁字体（734 字形 / 685 码位：ASCII、Latin-1、西里尔字母全覆盖；无 CJK）。注：原文行若为**非拉丁文字**（日文假名/汉字、韩文等）Sans 无字形 → 回退系统字体（拉丁语系与俄语无此问题）；若常处理此类语源再议；
- 两套字体**各字重都共用族名**（`Alibaba PuHuiTi 3.0` / `Alibaba Sans`）→ fontconfig 解析会撞车、选错字重；解决：随技能携带**只改族名、字形不动**的副本——`PuHuiTi-95`（中文）、`AlibabaSans-Bold`（英文）（fontTools 改 name 表 id 1/4/16/6 生成）；**两个 ttf 都放进 fontsdir**；
- ffmpeg 用 `ass=xxx.ass:fontsdir=<字体目录>` 引用，**不依赖系统安装**。

## 六、字幕封装与压制

- **压制时机（前置选项）**：默认**直接压制**；可选"**先出字幕、确认后再压制**"——先交 `<名称>.ass` 供用户挂原片确认，
  用户确认或提出修改后再烧录（修改走文本层编辑 + 机械重跑绑定/合并/打轴，亚秒级、不动编号与时间轴）；**用户未特别指定即直接压制**。
- **不压制（前置选项）**：只输出字幕文件（不下不发视频）——此时 ASS 用**系统默认字体**
  （`build_auto --font system`：中文 Microsoft YaHei、原文 Arial；该字体缺失时播放器回退其系统默认），**外挂播放无需安装任何字体**。
- **样式可采纳用户示例**：用户提供示例 `.ass` → `build_auto --style-from <示例.ass>` 采纳其**字体/字号/颜色/描边**
  （布局仍用我们的双固定水平）；该字体若未安装/不在 fontsdir，渲染会回退系统字体——要出硬字幕则需用户提供字体文件。
- **硬字幕（默认输出）**：ffmpeg + libass + fontsdir 烧录第五节 ASS 样式；必须重编码视频流、音频 `-c:a copy`；**编码方式用户可调**：
  · **编码档 = AI 判断 + 脚本直跑**：**能力判断交给 AI**——按硬件型号知识/现场查询决定编码档、用 `--codec` 传入
    （例：NVIDIA 20/30 系无 AV1 编码器 → `--codec hevc`；40/50 系 → `--codec av1`；拿不准就不传）；
    **脚本不做任何能力探测**（不试编一帧、不查型号表）——**直接跑真实编码**：指定了从该档开始、
    没指定按 **AV1 → HEVC → H.264** 预估顺序；失败**逐级下退、只向低效率方向**（不反向升级），
    **最终 CPU 兜底只做 H.264**（libx264 fast/crf20，**不用 CPU 压 AV1/HEVC**）；逐级下退在日志中标明；
  · **跨编码码率匹配（必守，禁止固定倍率）**：**目标码率 = 源码率 × 1.2（重编码余量）× EFF[输出]/EFF[源]**；
    EFF = 同画质所需码率（相对 h264=1.0）：**h264 1.0 / hevc 0.75 / vp9 0.8 / av1 0.7**（通用经验值；**"→AV1"方向为经验外推**——AV1 编码器仅见于较新硬件，无 AV1 编码器的机器会由试跑自动下退）。典型换算：
    AV1→HEVC ≈ **×1.29**、AV1→H.264 ≈ **×1.71**、**VP9→HEVC ≈ ×1.13、VP9→H.264 ≈ ×1.50**（VP9 为默认下载格式、最常用）、H.264→HEVC ≈ ×0.90、H.264→AV1 ≈ ×0.84、同编码 ×1.2
    （来源 5Mbps 为例：→HEVC 6.4M、→H.264 8.6M；**VP9 源 →HEVC 5.6M、→H.264 7.5M**；H.264 源 →HEVC 4.5M、→AV1 4.2M）——**固定倍率会让"高压缩效率的源"在低效率编码下折损画质**，故必须按 出/源 比值换算；
  · **硬件档参数（速度/体积/质量兼顾）**：**目标码率如上式**（`-rc vbr -b:v 目标 -maxrate 1.6× -bufsize 2×`）+ `-preset p5 -tune hq -multipass qres -rc-lookahead 20 -spatial-aq 1 -aq-strength 8`——**成片体积 ≈ 原片**（纯质量模式的体积可达数倍，故默认给码率封顶）；HEVC 同体积画质更高；参数组为**速度/质量折中**（质量优先项在旧一代 NVENC 上耗时成倍增加、画质增益极小；追求极限画质用 `--quality-first`）；
  · 可强制：`--codec av1|hevc|h264`（从该档开始）/ `--hw none`（只用 CPU）/ `--bitrate <bps>` / `--quality-first`（纯质量、体积数倍）；
  · **交付提示（AV1/HEVC 兼容性）**：AV1 / H.265 在 VLC/mpv/PotPlayer 等现代播放器正常，**Windows 自带播放器可能需装相应解码扩展**，个别剪辑软件/手机/网页上传可能不支持——**选项表与交付时都要提醒**，播放异常按 `--hw none` 重压即可；
  · 压完打印**体积对照**（成片 vs 原片、码率变化）；
  · **用户可自带 ffmpeg 参数**：`burn.py --ffmpeg-args "<参数>"`——追加在命令最后、同名参数以用户的为准
    （自定义编码器/参数；自带 `-vf` 会覆盖字幕滤镜，勿用）。
- **软字幕（可选，默认不输出）**：视频流**零重编码**（`-c copy`）、封装可开关的字幕轨——质量与原件完全一致。容器默认 **MKV + ASS 轨**（保留样式；如需 mp4 兼容（mov_text、丢样式）另议）。MKV 里**随片附带字体附件**（`PuHuiTi95.ttf` / `AlibabaSansBold.ttf`，`-attach` + mimetype）——ASS 用的族名是"改族名副本"、系统未安装，不附带则播放器会回退成别的字体、样式走样。**注：这是默认行为——只要输出软字幕就自动封装字体，不需要用户额外要求。**
